# Ассистент «Зал + Дела»: дизайн

Дата: 2026-10-29. Статус: согласовано с Амиром по разделам 1–2. Разделы 3–5 написаны по рекомендациям, Амир дал добро («делаю всё по твоим рекомендациям, не понравится — переделаем»).

## Цель

Бот и мини-апп становятся одним личным ассистентом. Зал (тренировки, питание, самочувствие, программа) остаётся как есть и отвечает по залу так же конкретно. К нему добавляются «Дела»: расписание уроков и пар, планы по датам, дедлайны, задачи, дела по дому, проекты (включая обучение) и заметки. Всё правится словами в боте (текст и голос, превью + «Применить») и в мини-аппе. Отдельный сайт `AventraLLC/amirs-hub` и его `data.js` уходят: данные переезжают в базу.

Критерии готовности:
- «В учёбу добавь сегодня в 11 позаниматься HTTP-сервером на C» → превью «В учёбу: … — сегодня в 11:00» → «Применить» → план в базе, виден в мини-аппе, напоминание за 30 минут.
- «Что у меня завтра?» → одно сообщение: пары, уроки, планы, тренировка, дедлайны.
- «Составь памятку по epoll» → бот пишет текст, «Сохранить» → заметка в разделе «Заметки».
- Еда, тренировки, самочувствие, правки программы работают как раньше; все существующие тесты зелёные.
- Утром в 08:00 (TIMEZONE) приходит сводка дня.

## Части и порядок

1. Данные «Дел» — таблицы, перенос из `data.js` и `hub_state`, сервис, API `/api/life/*`.
2. Мозг бота — маршрут сообщений, модель «Дел», памятки, ответы.
3. Напоминания и утренняя сводка.
4. Раздел «Дела» в мини-аппе + вход с компьютера; выключение `amirs-hub`.
5. Мост с компьютером (Obsidian, LearnHarness) — позже, своей спецификацией.

Части 2, 3, 4 зависят только от контрактов части 1 (таблицы, `services/life`, API) и могут идти параллельно.

## 1. Данные

Модуль `bot/src/gymbot/services/life.py` — единственный, кто пишет в эти таблицы. Все таблицы с `user_id` (владелец, `access.owner_user`), `created_at`, `updated_at`, мягкое удаление `deleted_at` (NULL = живая запись). Даты локальные (`TIMEZONE`), моменты в UTC. Миграция `0017_life`.

| Таблица | Поля |
|---|---|
| `life_slots` — расписание, каждую неделю | `weekday` 1..7, `start` "ЧЧ:ММ", `end` "ЧЧ:ММ"\|NULL, `title`, `area` (`work`\|`study`), `tag` (py, game, unity, web, vp, math, kg, study…)\|NULL, `place`\|NULL, `vld` "ЧЧ:ММ"\|NULL (срок заполнения после урока), `note`\|NULL |
| `life_events` — планы по датам | `day` date, `start` "ЧЧ:ММ"\|NULL, `end`\|NULL, `title`, `area` (`study`\|`work`\|`other`), `project_id`\|NULL, `remind_before` минут\|NULL (NULL = настройка по умолчанию), `reminded_at`\|NULL, `done_at`\|NULL, `note`\|NULL |
| `life_deadlines` | `day` date, `title`, `course`\|NULL, `project_id`\|NULL, `done_at`\|NULL, `reminded_on` date\|NULL |
| `life_tasks` | `title`, `tag`\|NULL, `project_id`\|NULL, `done_at`\|NULL, `position` int |
| `life_chores` | `title`, `every_days` int ≥ 1, `last_done` date\|NULL |
| `life_projects` | `name`, `kind` (`work`\|`learning`\|`own`), `status` (`active`\|`paused`\|`idea`\|`done`), `description`\|NULL, `link`\|NULL, `next_step`\|NULL |
| `life_notes` | `title`, `body` (Markdown), `tags` JSON list, `author` (`me`\|`bot`), `project_id`\|NULL |

Общие поля для всех: `source` (`me`\|`bot`\|`learnharness`\|`import`), `external_id`\|NULL (уникален вместе с `user_id` и `source`, для будущего моста). Настройки пользователя (в `users`, той же миграцией): `life_remind_before` (по умолчанию 30), `life_summary_minute` (по умолчанию 480 = 08:00), `life_summary_enabled` (true).

**Перенос** (`life.import_legacy`, вызывается при старте `main.py` один раз, отмечается в `users.life_imported_at`):
- `data.js` из `HUB_DIR` (читалка из `hub_tasks._array`): `lessons` → слоты `work` (`note`→`place`, `vld`), `study.classes` без `example` → слоты `study`, `study.deadlines` без `example` → дедлайны, `todos` → задачи (минус `removed`, `done` → `done_at`), `custom` из `hub_state` → задачи, `chores` → дела по дому (`last_done` из `hub_state.chores`), `projects` → проекты (`status` «в работе»→`active`, «учёба»→`active` + `kind=learning`, «идея»→`idea`; Менторика, AMGym → `work`, HTTP-сервер → `learning`, трекер идей → `own`).
- Нет `data.js` или owner — пропуск без ошибки, повтор при следующем старте.

**Сервис `life`** (чистые функции поверх сессии, без моделей и Telegram):
- `snapshot(session, user_id, today)` → датакласс `LifeView`: слоты недели, события на `today-1 … today+14`, открытые дедлайны, задачи (открытые + закрытые за 7 дней), дела по дому с `left` (дней до срока, < 0 просрочено), проекты (не `done`), заголовки заметок (последние 30).
- `day_agenda(view, day)` → упорядоченный список пунктов дня (слоты этого weekday, события дня, дедлайны дня, дела по дому со сроком ≤ 0) — общий для сводки, ответа «что у меня завтра?» и мини-аппа.
- `apply(session, user_id, actions, now)` → список изменённых сущностей; действия — dataclass'ы из раздела 2, валидация id внутри, неизвестный id = пропуск с заметкой.
- CRUD-хелперы для API.
- После любой записи — `live.publish(user_id, "life")` (новая тема в `live.TOPICS` и `miniapp/src/liveCore.ts`).

**API** (`bot/src/gymbot/api/life.py`, `APIRouter` с префиксом `/api/life`, подключается в `create_app` до монтирования мини-аппа; авторизация как у остального API — initData или токен входа с компьютера, см. раздел 4):
- `GET /api/life/view?date=ГГГГ-ММ-ДД` → `LifeView` + `agenda` на эту дату (по умолчанию сегодня).
- `POST|PATCH|DELETE /api/life/{kind}/{id}` для `slots|events|deadlines|tasks|chores|projects|notes`; `POST /api/life/chores/{id}/done`, `POST /api/life/tasks/{id}/done` (переключатель).
- Ответы — pydantic-модели в camelCase, как в остальном API мини-аппа.

Старые `/api/hub`, `/api/hub/state`, `/hub/`, `/api/hub/deploy` работают до конца части 4, потом `/hub/` перенаправляет в мини-апп, `hub_state` остаётся только для чтения переноса.

## 2. Мозг бота

Путь сообщения в `handlers/log_text.process_text` (голос — тот же путь):

1. Быстрые слова (`life_gate.is_life_command`: задач, туду, в дела, учёб, позаниматься, дедлайн, экзамен, зачёт, сдать, заметк, памятк, конспект, расписани, запланир, в планы, урок, пар[аыу], дела по дому, убрался, уборк, стирк, вынес мусор, закупил продукты, коммунал, проект) → модель «Дел». Если модель вернула 0 действий — дальше как раньше. Заменяет нынешний гейт `hub` (тот же порядок: после карточек продуктов, до правок программы).
2. Правки программы, правки записей, вес — как сейчас.
3. Разборщик зала: новый `kind = "life"` в `ParseResult` (одна строка в промпте: «задачи, учёба, расписание, дела по дому, заметки, памятки, проекты — kind life, остальные поля пустые»). `kind == "life"` → модель «Дел» без проверки слов; 0 действий → ответ «Не понял, что сделать в делах» с примером.
4. Вопрос → ответ дневника. В сводку ответа (`services/answer.gather`) добавляется блок «Дела» (`life.day_agenda` на сегодня и завтра, открытые задачи, ближайшие дедлайны, проекты обучения со следующим шагом, заголовки заметок). Промпт ответа: «ты личный ассистент Амира; по залу — из дневника; общие вопросы (как работает epoll) — отвечай по существу; изменить что-то в делах — последняя строка `ДЕЛА: <команда>`». `split_command` распознаёт и `ПРАВКА:`, и `ДЕЛА:`; `ДЕЛА:` ставится в превью модели «Дел» под ответом.

**Модель «Дел»** (`llm/prompts_life.py`, `purpose="json"`): системный промпт стабильный, в пользовательском ходе — дата, день недели, `LifeView` в компактном тексте с id. Ответ `{"actions": [...], "question": null | {"text", "options": [..≤4]}}`. Действия (`services/life_actions.py`, разбор и валидация):

- `add` / `update` / `remove` с полем `entity` (`slot|event|deadline|task|chore|project|note`), `id` (для update/remove), `fields` (подмножество полей таблицы своего вида);
- `done` / `undone` для `task|event|deadline|chore` (`chore` + необязательная `date`);
- `write_note` `{title, brief, project_id?}` — бот сам пишет текст;
- `edit_note` `{id, instruction}` — переписать заметку по указанию;
- `settings` `{remind_before?, summary_time? "ЧЧ:ММ", summary_enabled?}` — настройки напоминаний и сводки.

Даты модель считает от сегодняшней даты в контексте; код проверяет диапазон (±400 дней) и формат времени. Новые id не нужны: создание идёт при «Применить».

**Превью**: `handlers/life.py` (замена `handlers/hub.py`): строки вида «В учёбу: «…» — сегодня в 11:00», «Закрою задачу «…»», «Перенесу «ИЗ Математика» с пн на вт». Кнопки «✅ Применить» / «Отмена», черновик в памяти 15 минут, первое нажатие забирает. `write_note`/`edit_note`: второй запрос `complete_text` (purpose `advice`) пишет Markdown, превью — заголовок и первые ~600 символов, кнопки «Сохранить» / «Отмена»; пока превью открыто, сообщение «добавь пример», «короче» переписывает черновик (контекст — черновик + указание). После применения — «Готово» + кнопка «Открыть дела» (мини-апп на разделе «Дела»). `/hub` переименовывается в `/life` (старый остаётся синонимом).

Модуль `services/hub_tasks.py` и `handlers/hub.py` удаляются после переноса, их тесты переписываются на новые модули.

## 3. Напоминания и сводка

Отдельный цикл не нужен: `services/reminders.reminder_loop` раз в минуту дополнительно вызывает `life_reminders.tick(now)`.

- **Планы по датам со временем**: когда `start − remind_before ≤ сейчас < start` и `reminded_at IS NULL` — сообщение «Через 30 мин (11:00): Позаниматься HTTP-сервером на C» с кнопками «✅ Сделано» и «+30 мин» (сдвигает `start` и `end` на 30 минут, сбрасывает `reminded_at`). `reminded_at` ставится до отправки (защита от дублей, как у напоминаний).
- **Слоты расписания** не напоминаются (это ежедневная рутина), но входят в сводку.
- **Дедлайны**: в сводке за 3 дня и в день; отдельное сообщение накануне в 20:00 (`reminded_on`).
- **Утренняя сводка** в `life_summary_minute` (по умолчанию 08:00): без модели, детерминированный текст из `day_agenda` + тренировка дня по программе (`plan.collect_inputs` не нужен — `programs.find_day`), задачи (до 5 открытых), дела по дому со сроком, следующий шаг проектов обучения. Кнопка «Открыть дела». Отключается и переносится словами («сводку присылай в 7», «не присылай сводку») — действие `settings` модели «Дел».
- Всё в HTML-карточке, как `/today` (`services/tg_html`).

## 4. Мини-апп

- Вверху переключатель «Зал | Дела» (запоминается в localStorage, `?section=life` открывает «Дела»). «Зал» — нынешние 5 вкладок без изменений.
- «Дела» — свои вкладки: **Сегодня** (повестка дня по времени, дела по дому со сроком, дедлайны ≤ 3 дней, топ задач), **Расписание** (неделя: слоты + планы, листание недель, дедлайны), **Задачи** (задачи + «Дом»), **Проекты** (по виду: работа / обучение / своё, задачи проекта, следующий шаг), **Заметки** (список, просмотр Markdown, правка текста).
- Всё на `/api/life/*`, обновление по live-теме `life`. Добавление и правка — простые листы (`Sheet`), удаление с подтверждением.
- **Вход с компьютера**: команда `/web` присылает ссылку `https://<PUBLIC_URL>/#login=<токен>` (во фрагменте: серверу и в журналы не уходит); токен — HMAC (`live`-подобный, назначение `web-login`, 30 дней), `/web выйти` отзывает все выданные (`users.web_login_since`), мини-апп кладёт его в localStorage и шлёт заголовком `X-App-Token`; сервер принимает его там же, где initData. Вне Telegram без токена — экран «Открой /web в боте».
- После выката: `/hub/` → 302 на `/?section=life`; `amirs-hub` архивируется Амиром (его workflow и ключ развёртывания можно оставить).

## 5. Мост с компьютером (позже)

Отдельная спецификация. Заложено сейчас: `source`, `external_id`, Markdown в заметках, проекты `learning`. Идея: агент на компьютере читает `LearnHarness/data/chats/*.json` и `practice/*.json` → проекты обучения (цель, прогресс плана), задачи «практика ждёт»; пишет заметки в хранилище Obsidian; ходит в бота через `/api/life` с токеном `/web`.

## Ошибки и надёжность

- Любая ошибка модели «Дел» на пути быстрых слов → сообщение идёт дальше обычным путём (как сейчас у правок программы).
- Запись только после кнопки; повторное нажатие — «Устарело».
- Миграция данных идемпотентна, ничего не удаляет из `hub_state`.
- Напоминания: отметка до отправки, сбой отправки логируется и не повторяется в ту же минуту.
